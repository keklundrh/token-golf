## Critical Bugs Fixed (Tier 1)

### 1. Session Creation - Missing course_total_holes ✅
**Issue**: New sessions defaulted to 5 holes regardless of actual course configuration. Completion detection failed for beginner-course (2 holes) and other non-full-tour courses.

**Fix**: Added `course_total_holes=len(challenge_ids)` to Session constructor in `app/api/game.py:467`.

**Impact**: Completion tracking now works correctly for all course types.

---

### 2. Session Completion Status ✅
**Issue**: Finished courses vanished from global leaderboard after timeout. Sessions were never marked as 'completed', only 'active' or 'dnf'. The global leaderboard filter `Session.status != "dnf"` erased completed sessions after 3h timeout, violating ADR 010.

**Fix**: Removed `Session.status != "dnf"` filter in `app/services/scoring.py:549`. Participant completion (`course_completed_at`) now determines global leaderboard inclusion, not session status.

**Impact**: Users who finish before timeout now remain on global leaderboard permanently.

---

### 3. Alpine.js Frontend Bugs ✅
**Issues**:
- `x-text="holesCompleted"` referenced undefined Alpine variable
- `@click.away` used Alpine v2 syntax (should be `@click.outside` for Alpine 3)
- localStorage/sessionStorage mismatch broke "My Session" view
- System prompt display missing

**Fixes**:
- Added `holesCompleted` to statsPanel() Alpine data
- Fixed `@click.away` → `@click.outside`
- Unified storage to use sessionStorage consistently
- Added system prompt read-only display section

**Location**: `app/templates/game.html`, `app/templates/leaderboard.html`

**Impact**: UI now functions correctly with proper Alpine 3 syntax.

---

### 4. Test Suite ADR 010 Schema Updates ✅
**Issue**: Leaderboard tests expected old `{entries: [...]}` schema. ADR 010 changed session leaderboards to `{completed: [...], in_progress: [...]}`.

**Fix**: Updated all session leaderboard tests to use new two-section schema:
- `tests/integration/test_api_leaderboard.py`
- `tests/e2e/test_complete_game_flow.py`
- `tests/e2e/test_multiplayer_session.py`

**Impact**: Tests now match actual API responses.

**Fix**: Added Session object creation to all scoring tests in `tests/unit/test_scoring.py`.

**Impact**: Scoring tests now pass with proper database setup.

## Security Fixes (Tier 2)

### 7. Sandboxed Code Execution ✅
**Issue**: Arbitrary LLM output exec()'d in-process with no sandbox or timeout. Infinite loops blocked event loop; malicious code ran with server privileges.

**Fix**: Implemented restricted execution in `app/services/validator.py:365`:
- Restricted `__builtins__` (removed file I/O, os, subprocess, network access)
- Timeout enforcement via signal (Unix-only, 1-10 seconds)
- Clear security warning for production containerization

**Impact**: Significantly reduced attack surface. Still requires Docker/podman for production.

---

### 8. Exception Handling Specificity ✅
**Issue**: `except Exception` in `app/api/game.py:629` caught all errors as "weather delay", including validation errors like `ValueError: Prompt cannot be empty`.

**Fix**: Changed to specific exception types:
```python
except (ConnectionError, TimeoutError, RuntimeError) as e:
```

**Impact**: Only LLM-related errors trigger weather delay. Validation errors propagate correctly.

---
